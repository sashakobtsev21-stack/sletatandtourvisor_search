# Подключение новой площадки

Полное руководство: какие данные нужны и что реализовать, чтобы **новая площадка
искала идентично Tourvisor и Sletat**. Цель — чтобы при одном наборе параметров от
пользователя на всех подключённых площадках подставлялись **одни и те же,
корректные данные**, а результаты можно было честно сравнивать.

Читать вместе с [`OPERATOR_MAPPING.md`](OPERATOR_MAPPING.md) (сопоставление операторов)
и [`../SITES.md`](../SITES.md) (особенности конкретных сайтов).

---

## 1. Главный принцип: один канон → перевод на каждую площадку

Пользователь вводит параметры **один раз**, в едином формате
(`models.SearchParams`). Оркестратор отдаёт **один и тот же** `SearchParams`
каждому провайдеру. Провайдер — единственное место, которое знает про конкретный
сайт: он **переводит** канонические значения в действия на своей форме и парсит
результат обратно в единый `ProviderResult`.

```
Пользователь → SearchParams (канон) ──┬─► SletatProvider   → ProviderResult ┐
                                      ├─► TourvisorProvider → ProviderResult ├─► ComparisonReport
                                      └─► НоваяПлощадка     → ProviderResult ┘
```

Из этого вытекает золотое правило: **канонические значения нельзя «подгонять» под
площадку в форме или на фронте**. Любое расхождение в написании/кодировке решается
внутри провайдера (через справочник/алиасы), а не правкой канона.

## 2. Контракт входных данных — `SearchParams`

Это **исчерпывающий** список того, что пользователь может задать. Новая площадка
обязана осмысленно отработать каждое поле, которое она поддерживает, и **молча
игнорировать** неподдерживаемые (не падать).

| Поле | Тип | Что значит | Как мапить на площадку |
|------|-----|-----------|------------------------|
| `departure_city` | str | Город вылета (канон. имя из `refdata.DEPARTURE_CITIES`) | Найти в справочнике вылетов площадки → её id/slug |
| `destination_country` | str | Страна (ключ `refdata.COUNTRIES`) | Найти в справочнике стран площадки → id/slug |
| `date_from` / `date_to` | date | Окно даты вылета (туры) / заезда (отели) | Формат даты площадки; см. §6 про режим «отели» |
| `nights_min` / `nights_max` | int ≥1 | Диапазон ночей | Поля «ночей от/до». В отелях — задаётся диапазоном дат |
| `adults` | int ≥1 | Взрослых | Селект «взрослые» |
| `children_ages` | list[int] 0..17 | Возраст каждого ребёнка | Кол-во детей + возраст каждого |
| `search_mode` | `tours`/`hotels` | Тур с перелётом / только отель | Выбор раздела/режима на площадке |
| `resorts` | list[str] | Курорты/города прилёта (пусто = любой) | Справочник курортов страны → id/slug |
| `hotel_stars` | list[int] 1..5 | Звёздность (пусто = любая) | Чекбоксы/мультиселект звёзд |
| `meals` | list[str] из `MEAL_CODES` | Питание (пусто = любое) | Перевод кодов в подписи площадки (см. §3.5) |
| `hotel_types` | list[str] | Типы отелей | Если поддерживается |
| `hotels` | list[str] | Конкретные отели (имена/ID) | Поиск отеля по имени |
| `hotel_rating_min` | float\|None | Мин. рейтинг | Если поддерживается |
| `operators` | list[str] | Туроператоры (пусто = все) | Сопоставление + выбор (см. §3.1) |
| `charter_only` | bool | Только чартер | Чекбокс |
| `direct_only` | bool | Только прямой рейс | Чекбокс |
| `no_stops` | bool | Без пересадок | Чекбокс |
| `with_transfer` | bool | С трансфером | Чекбокс |
| `instant_confirmation` | bool | Моментальное подтверждение | Чекбокс |
| `price_min` / `price_max` | Decimal\|None | Диапазон цены | Поля цены |
| `currency` | str | Валюта (`RUB` по умолч.) | Селект валюты |
| `sort_by` | `price`/`popularity` | Сортировка | По умолчанию `price` — для надёжной мин. цены |

**Инвариант:** при одинаковом `SearchParams` все площадки ищут одно и то же. Если
площадка чего-то не умеет — она это поле опускает, но **остальные параметры
обязана выставить точно**, иначе цены несравнимы.

## 3. Справочные данные, которые нужно сопоставить с каноном

Канон хранится в [`src/toursearch/refdata.py`](../src/toursearch/refdata.py):
`OPERATORS`, `DEPARTURE_CITIES`, `COUNTRIES` (страна → курорты). Для каждой новой
площадки нужно **спарсить её собственные справочники** и сопоставить с каноном.

### 3.1. Туроператоры — обязательно

- **Канон:** список Sletat (`refdata.OPERATORS`, отдаётся фронту).
- **Что сделать для площадки:** спарсить её список операторов с сайта и
  сопоставить с каноном. Алгоритм (норма + регион + алиасы) уже реализован для
  Tourvisor — переиспользовать его. Подробная таблица и правила —
  [`OPERATOR_MAPPING.md`](OPERATOR_MAPPING.md).
- **Где взять список:** у Tourvisor это JSON `listdev.php` (`lists.operators[].name`).
  У новой площадки — найти аналогичный справочник (JSON-эндпоинт формы, либо
  распарсить DOM списка операторов).
- **Отсутствующий оператор** → провайдер пропускает его, не падая.

### 3.2. Страны — обязательно

- **Канон:** ключи `refdata.COUNTRIES`.
- **Площадка:** справочник стран → внутренний `id`/`slug`. У Tourvisor — `listdev.php`
  (`lists.countries`), id используется в форме, slug — в «красивых» URL `/tours/{country}/...`.
- Сопоставление по имени с нормализацией; редкие/региональные написания — алиасом.

### 3.3. Города вылета — обязательно

- **Канон:** `refdata.DEPARTURE_CITIES` (Россия + Грузия/Казахстан/Узбекистан/Беларусь).
- **Площадка:** справочник вылетов → id/slug (Tourvisor: `listdev.php` `departures`).
- ⚠️ **Связь вылет↔страна.** На некоторых площадках смена города вылета **сбрасывает
  выбранную страну** и/или ограничивает доступные страны (см. §8 про Tourvisor).
  Это нужно проверять при подключении и обрабатывать.

### 3.4. Курорты / города прилёта

- **Канон:** значения `refdata.COUNTRIES[country]`.
- **Площадка:** справочник курортов выбранной страны → id/slug. Сопоставление по
  имени с нормализацией.

### 3.5. Питание — словарь кодов

Канон — `models.MEAL_CODES = {none, BB, HB, FB, AI, UAI}`. Каждая площадка мапит код
в свою подпись:

| Код | Значение | Типичные подписи |
|-----|----------|------------------|
| `none` | без питания | RO / OB / «без питания» |
| `BB` | завтрак | BB / «завтрак» |
| `HB` | завтрак+ужин | HB / «полупансион» |
| `FB` | 3-разовое | FB / «полный пансион» |
| `AI` | всё включено | AI / «все включено» |
| `UAI` | ультра всё включено | UAI / «ультра все включено» |

### 3.6. Прочее с фиксированной шкалой

- **Звёзды:** 1..5 (валидируется в `SearchParams`).
- **Ночи / взрослые / дети:** числовые, прямой перенос; детям — возраст каждого.
- **Флаги рейса/опций:** булевы чекбоксы (см. таблицу §2).
- **Валюта/сортировка:** селекты; `sort_by=price` по умолчанию.

## 4. Где брать справочники площадки (паттерн Tourvisor)

Хороший способ — найти **JSON-эндпоинт справочников**, который форма дёргает сама.
У Tourvisor это `listdev.php`:

```python
# Слушаем ответы страницы и ловим listdev с операторами:
page.on("response", lambda r: capture(r) if "listdev.php" in r.url and "operator" in r.url else None)
await page.goto(HOMEPAGE_URL); await page.click("div.TVCountryFilter")
data = await captured.json()
countries  = data["lists"]["countries"]    # id, name, slug
departures = data["lists"]["departures"]   # id, name, slug
operators  = data["lists"]["operators"]    # id, name, fullname, russian, active
```

Если у новой площадки нет такого JSON — справочники парсятся из DOM списков
(операторы, страны, города) при открытии соответствующих фильтров. Главное —
**один раз** получить полные списки и зафиксировать сопоставление с каноном
(как в `OPERATOR_MAPPING.md`).

## 5. Реализация провайдера

Контракт — [`providers/base.py`](../src/toursearch/providers/base.py):
`SearchProvider` (Protocol) + декоратор `@register_provider("имя")`.

```python
from toursearch.providers.base import SearchProvider, register_provider, start_frame_pump, stop_frame_pump
from toursearch.models import ProviderResult, SearchParams

@register_provider("newsite")
class NewSiteProvider:
    name = "newsite"

    def __init__(self, headless: bool = True):
        self.headless = headless

    async def search(self, params: SearchParams) -> ProviderResult:
        # 1) открыть форму, выбрать режим (tours/hotels)
        # 2) выставить ВСЕ поддерживаемые поля SearchParams (см. §2)
        #    — справочники → id/slug через сопоставление (§3)
        # 3) сверить форму перед запуском (см. §7)
        # 4) кликнуть «Найти», дождаться завершения, замерить время
        # 5) распарсить предложения и собрать ProviderResult
        ...
```

Регистрация в `providers/__init__.py` (импорт модуля, чтобы декоратор сработал).
Оркестратор и сравнение работают только через реестр и про сайт ничего не знают.

### Что вернуть — `ProviderResult` (см. [`models.py`](../src/toursearch/models.py))

| Поле | Заполнять |
|------|-----------|
| `provider` | `self.name` |
| `success` | удалось ли довести поиск |
| `duration_seconds` | от клика «Найти» до полного завершения |
| `search_mode` | из params |
| `offers` | режим «Туры»: `Offer(provider, operator, price, currency)` |
| `hotel_offers` | режим «Отели»: `HotelOffer(provider, hotel_name, price, stars, …)` |
| `operator_offers` | разрез по оператору: `OperatorOffer(operator, price, hotel_name?, load_seconds?)` — `load_seconds` = за сколько секунд у оператора появилась цена (best-effort, можно None) |
| `error` | текст ошибки при `success=False` |
| `screenshot_path` | путь к финальному скриншоту результатов |
| `search_url` | прямой URL результата, если площадка его формирует |

Цены — `Decimal`, в одной валюте (`currency`), чтобы сравнение было корректным.

## 6. Режимы «Туры» vs «Отели»

- **Туры** (`search_mode=tours`): с перелётом. Ночи задаются полями «от/до».
- **Отели** (`search_mode=hotels`): только проживание, без перелёта. На многих
  площадках в этом режиме **нет отдельного выбора ночей** — длительность задаётся
  **диапазоном дат заезда/выезда** (`date_from`..`date_to`). У Tourvisor в разделе
  отелей фильтр дат вылета `.TVFlyDatesFilter` скрыт — используется
  `.TVTripDurationFilter`. На новой площадке проверить аналогичное поведение и
  при необходимости не сверять `date_to` буквально (см. `urlcheck.py`, hotels-режим).

## 7. Проверка формы и здоровья (health-anchors)

Перед запуском поиск нужно **сверить**, что форма действительно настроена как в
`SearchParams` (а не сбросилась). Паттерны в проекте:

- [`urlcheck.py`](../src/toursearch/urlcheck.py) — сверка параметров по URL результата
  (в режиме «отели» `dateto` может не сверяться — off-by-one из-за диапазона дат).
- [`providers/_formcheck.py`](../src/toursearch/providers/_formcheck.py) — сверка
  состояния полей формы; несовпадение critical-полей → `FormVerificationError`.
  Операторы сделаны **non-blocking**: их рассинхрон логируется warning'ом, но не
  валит поиск (площадка могла переименовать/виртуализировать список).
- **Health-anchors** — стабильные селекторы-«якоря», по которым видно, что страница/
  виджет прогрузились (заголовок календаря, контейнер списка операторов и т.п.).
  Для новой площадки зафиксировать такие якоря и ждать их (`wait_for_selector`).

**Живые кадры/скриншоты.** `start_frame_pump/stop_frame_pump` (base.py) отдают live-jpeg
вкладки в веб; `capture_top` снимает верх страницы с результатами. Новой площадке
достаточно прокинуть `on_frame` и снять финальный скриншот — UI это покажет.

## 8. Известные ограничения площадок (учесть при подключении)

- **Tourvisor + не-Москва + редкая страна.** При городе вылета ≠ Москва Tourvisor
  сбрасывает страну на дефолтную (Турция), а ленивый список «Все страны» не
  дорисовывается в headless. Прямые `/tours/{country}/{city}` работают только для
  заранее зарегистрированных комбинаций; `search.php` игнорирует произвольный
  `s_country`. Вывод (принят пользователем — «Вариант А»): Sletat покрывает все
  страны/города; Tourvisor — где возможно. Для новой площадки **проверять такие
  стены заранее** и фиксировать в `SITES.md`.
- **Нормализация имён** обязательна везде (операторы/страны/курорты): разный
  алфавит, регистр, `&`/`and`, региональные суффиксы.

## 9. Алгоритм нормализации (единый для всех справочников)

Применять при сопоставлении любых имён (операторы, страны, курорты):

1. **region(s)** — суффикс `(BY)/(KZ)/(UZ)`, если есть (иначе пусто). Кандидаты —
   только того же региона.
2. **core(s)** — `lowercase`, убрать скобки `(…)`, убрать слова `and`/`и`, оставить
   только буквы/цифры (латиница+кириллица).
3. Сопоставление: точное совпадение `core` → затем вхождение в любую сторону.
4. Что не закрылось — **алиас** (нормализованное имя канона → точное имя площадки).

Ссылочная реализация — `providers/tourvisor.py` (`_operator_norm`,
`_TV_OPERATOR_ALIASES`, JS-матчинг в `_select_operators`) и скрипт
`scripts/_map_operators.py`.
