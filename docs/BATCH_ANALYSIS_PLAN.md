# План: батч-анализ по многим направлениям + ЛК, уведомления, экспорт

## Сценарий (со слов владельца)
Туроператор хочет сравнить выдачу туров сразу по МНОГИМ направлениям (напр. 20). UX:
- поле выбора направлений с **множественным** выбором;
- ниже — окошко со списком выбранного, из которого можно **удалять** позиции;
- отдельная кнопка **«Запустить анализ»**;
- после запуска поиск идёт **в фоне**; по готовности — **уведомление на сайте** «готово, можно
  посмотреть» **и письмо на почту** со ссылкой на **личный кабинет**, где виден отчёт;
- из ЛК можно **скачать отчёт в Excel или CSV**.

## Архитектура (ключевые изменения)
Сейчас поиск = одно направление → 5 площадок, живёт в памяти (`_SearchSession`), привязан к
SSE. Батч из 20 направлений идёт минутами (20×~60с, при пределе 3 одновременных ≈ 7+ мин) —
значит нужна **долгоживущая фоновая задача**, не привязанная к соединению.

- **Таблица `jobs`** (durable): id, user_id, status (pending/running/done/failed), params (общие
  параметры + список направлений JSON), progress (готово/всего), created_at, finished_at. Каждое
  направление → отдельный прогон (`runs`), связанный с job (`runs.job_id`). Отчёт батча = все
  прогоны job.
- **Воркер:** asyncio-задача гоняет направления (с учётом предела одновременных), пишет прогресс
  в `jobs`. На рестарте сервера незавершённые → помечать `failed/interrupted` (одно-процессный
  uvicorn; полноценная очередь — позже при масштабе).
- **Кредиты:** батч из N направлений = **N поисков** (списываем по мере выполнения каждого;
  возврат за сбойные — как в одиночном поиске).
- **Уведомления (в приложении):** таблица `notifications` (user_id, тип, job_id, текст, read,
  created_at) + `GET /api/notifications` (фронт поллит/значок) → «батч #X готов».
- **Почта:** SMTP (env-креды; RU — Yandex/Mail.ru/Unisender/SendPulse). Письмо «анализ готов» +
  ссылка `/app/#/jobs/<id>`. Нужна инфраструктура отправки (модуль `mailer.py`).
- **Личный кабинет (ЛК):** страница «Мои анализы» — список job'ов (статус/прогресс/дата) →
  открыть отчёт батча. Частично переиспользует историю прогонов.
- **Экспорт Excel/CSV:** `GET /api/jobs/<id>/export?fmt=xlsx|csv` → файл. CSV — stdlib; XLSX — нужна
  зависимость (`openpyxl`). Колонки: направление · площадка · оператор/отель · цена · скорость · ссылка.

## Фазы внедрения
- **Ф1 — мульти-выбор + батч-бэкенд:** поле множественного выбора направлений + чипы-список с
  удалением + «Запустить анализ»; `jobs`-таблица + воркер (N прогонов, списание N кредитов);
  статус батча в UI (прогресс). Без почты — пока в приложении видно «идёт/готово».
- **Ф2 — ЛК + уведомления в приложении:** страница «Мои анализы» (список job'ов + отчёт батча);
  `notifications` + значок «готово».
- **Ф3 — экспорт:** CSV (stdlib) + XLSX (`openpyxl`) из ЛК.
- **Ф4 — почта:** `mailer.py` (SMTP, env) + письмо со ссылкой на ЛК по готовности. Нужны
  SMTP-креды (и желательно домен для нормальной доставляемости).
- **Фаза B (биллинг) — анонимные 3 поиска:** см. `docs/BILLING_PLAN.md` (гостевой режим SPA +
  квота cookie+IP + анти-абьюз) — параллельный трек.

## Зависимости / решения
- Зависимости: `openpyxl` (XLSX); почта — SMTP-провайдер (выбор за владельцем).
- Долговечность job'ов на рестарт: MVP — помечать прерванные; очередь (RQ/Celery) — только при
  реальном масштабе.
- Экономику батчей (N кредитов за N направлений) уточняет аудит рынка (см. ниже).
