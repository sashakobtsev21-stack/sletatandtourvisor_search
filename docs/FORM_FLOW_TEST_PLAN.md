# План тестов формы анализа (поток: данные → запрос → ответ) по всем площадкам

Цель тестов — проверять **реальный поток формы анализа**, а не покрытие кода:
что в форму попадают **верные данные**, что они **корректно отправляются** на каждую
площадку и что **ответы площадок читаются** правильно. На всех 5 площадках
(Sletat, Tourvisor, Travelata, Level, Ostrovok) + сверка площадок между собой.

## Три стадии (что именно проверяем)

1. **Данные используются** — параметры поиска корректно доходят до провайдера
   (форма → `SearchParams` проверяется в `tests/test_web_search.py`; провайдер строит
   запрос из этих параметров).
2. **Запрос отправляется верно** — URL результата на площадке **кодирует заданные
   параметры**. Сверка per-provider: `verify_{sletat,tourvisor,travelata,level,ostrovok}_search_url`
   на ЖИВОМ `page.url` после поиска (`flowkit.sent_ok`). Доказывает: «задали правильный вопрос».
3. **Ответ читается верно** — распарсенные данные осмысленны: цена > 0, валюта задана,
   рейтинг 0–10, звёзды 1–5, имена непустые, операторы без дублей (`dataquality.check_result`
   на РЕАЛЬНОЙ выдаче, `flowkit.read_ok`). Плюс **честность фильтров**: звёзды/рейтинг/цена
   в выдаче соответствуют запросу (`flowkit.stars_honored/rating_honored/price_honored`).

## Сверка результатов площадок (cross-platform)

Один и тот же запрос уходит на все применимые площадки → `crosscheck.crosscheck`
(`flowkit.consistent`): единая валюта, каждая цена в правдоподобном диапазоне
[1 000, 5 000 000] ₽, минимальные цены площадок не расходятся более чем в 8× (грубый
детектор «кто-то ищет/парсит/считает не то»), и у каждой успешной площадки данные
корректны.

## Где код

| Модуль | Роль |
|---|---|
| `testkit/flowkit.py` | провайдеро-агностичный прогон потока + стадии (sent_ok / read_ok / honored / flow_ok / consistent) |
| `dataquality.py` | инварианты корректности данных одной площадки (применяются к реальной выдаче) |
| `crosscheck.py` | сверка результатов разных площадок по одному запросу |
| `testkit/scenariokit.py` | углублённые сценарные проверки Sletat (исторически богатые) |
| `testkit/catalog.py` | регистрация кейсов в реестр (видны в веб-панели «Тесты») |

## Группы в каталоге (веб-панель «Тесты»)

- `Live: Сценарий — поток {Sletat|Tourvisor|Travelata|Level|Ostrovok}` — поток формы по
  каждой площадке (базовый поиск + направления + город вылета + дети + звёзды/цена/питание,
  режимы «Туры»/«Отели»). Неподдерживаемый режим → ожидается чистый отказ.
- `Live: Сверка площадок` — один запрос на все площадки → согласованность + корректность.

Базовые кейсы требуют результатов (Турция — плотная выдача); вариации — нет (наличие
зависит от дат/направления, поэтому проверяется КОРРЕКТНОСТЬ ПОТОКА, а не наличие туров).

## Как запускать

- Веб-панель «Тесты» (с рабочего стола) → выбрать группы `Live: …` → «Запустить».
- Дымовой тест каркаса: `.venv\Scripts\python.exe scripts\smoke_flowkit.py`.
- Параллелизм live-прогона: `TOURSEARCH_TEST_CONCURRENCY` (по умолчанию 4).

Группы `Live: Сценарий — поток …` гоняются конкурентно (каждый кейс — свой браузер),
`Live: Сверка площадок` — последовательно (каждый кейс поднимает несколько браузеров).
