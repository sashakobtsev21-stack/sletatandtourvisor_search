# План внедрения оплаты (SaaS-подписка)

Монетизация — **подписка на доступ к агрегатору** поверх существующей авторизации
(`users`/роли). Ложится на текущий стек: FastAPI + SQLite + React.

## Принятые решения
| Вопрос | Решение |
|---|---|
| Модель | **SaaS-подписка**: платят за доступ к сервису (срок `paid_until`). |
| Граница бесплатно/платно | **бесплатно** — регистрация + просмотр своей истории; **платно** — запуск анализа (право `search.run`). |
| Юр-статус | **Старт как самозанятый (НПД)**, переход на ИП при перерастании (доход >2.4 млн/год или сотрудники). Самозанятый освобождён от онлайн-кассы 54-ФЗ — чек через «Мой налог»/провайдера. |
| Провайдер | **ЮKassa** (поддержка самозанятых, авто-чек, redirect+webhook, рекуррентные, тестовый магазин, SDK). СБП — позже (ниже комиссия). |
| admin | подписку не требует (бесплатный полный доступ — это владелец/персонал). |

## Архитектура
- **Данные (`users`):** `plan TEXT DEFAULT 'free'`, `paid_until TEXT` (UTC ISO, NULL = нет подписки).
  Таблица `payments` (Ф1): провайдерские платежи для идемпотентности/аудита.
- **`billing.py`:** `subscription_active(user)` (paid_until в будущем), `access_allowed(user)`
  (admin ИЛИ активная подписка), `PAID_PERMISSION = "search.run"`.
- **Гейтинг:** в middleware (`web_auth.py`) после проверки права — если путь требует
  `search.run` и `not access_allowed(user)` → **402 Payment Required**. Локальный/legacy режимы
  не трогаются (гейт только в мультиюзере).
- **Выдача подписки:** CLI `toursearch grant-sub --username … --days N` (комп-аккаунты, ручные
  платежи, тесты). В Ф1 продление делает вебхук провайдера.

## Фазы
- **Ф0 (эта итерация):** `users.plan/paid_until` + миграция; `billing.subscription_active/access_allowed`;
  `storage.grant_subscription`; гейт `search.run` по подписке (admin байпас); CLI `grant-sub`. Тесты.
  Делается и тестируется БЕЗ провайдера и деплоя.
- **Ф1:** ЮKassa — таблица `payments`, `POST /api/billing/checkout` (создать платёж → confirmation_url),
  `POST /api/billing/webhook` (перезапрос-проверка платежа по id + идемпотентное продление),
  `GET /api/billing/status`. Тесты на моках. Зависимость: SDK `yookassa` (для денег корректность > минимализм).
- **Ф2:** фронт — страница «Подписка» (план/срок + «Оплатить» → редирект → возврат), обработка 402
  (показать «нужна подписка»), гашение формы без подписки.
- **Ф3:** закалка — секреты в env, тестовый режим, возвраты (refund), оферта + политика.

## Засады (важно)
- **Вебхук требует публичного HTTPS** → платежи завязаны на deploy-историю (домен + TLS).
  Локально вебхук тестируется только через туннель (ngrok/cloudflared). Ф0/Ф2-UI от этого не зависят.
- **Секреты ЮKassa** (`shopId`/`secretKey`) — через env, не в гит.
- **Идемпотентность:** `payments.provider_payment_id` уникален; продление `paid_until` — один раз на платёж.
- **Юридически:** публичная оферта + политика конфиденциальности обязательны для приёма платежей.
- **402 без UI** до Ф2: бэкенд вернёт 402, SPA покажет как ошибку поиска — нормально для промежутка.
