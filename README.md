# Tour Search — сравнение поиска туров на нескольких площадках

> Раньше проект назывался *ТурСравнение / toursearch*; пакет в коде по‑прежнему `toursearch`.

Сервис принимает параметры поиска, открывает несколько онлайн‑площадок
(**Sletat** — главная, **Tourvisor**) через headless‑браузер, выставляет заданные
фильтры, дожидается полной загрузки результатов, сохраняет их и **сравнивает**:
минимальная цена, по какому туроператору/отелю, лучший вариант и время выполнения
поиска на каждой площадке.

**Стек:** Python 3.12+, Playwright (async), pydantic v2, SQLite, FastAPI, pytest.
Фронт‑дашборд — React 18 + Vite + Tailwind + framer‑motion.

> 📘 Не разработчик? Загляни в **[docs/КАК_УСТРОЕН_ПРОЕКТ.md](docs/КАК_УСТРОЕН_ПРОЕКТ.md)** —
> разбор «для любителя»: что это, как пользоваться и как всё работает простыми словами.

## Возможности

- **Два режима поиска:** «Туры» (с перелётом) и «Отели» (без перелёта; на Sletat ночи
  в этом режиме задаются датами проживания, не отдельным контролом).
- **Полный набор фильтров:** город вылета, страна и курорт прилёта, даты, ночи,
  взрослые и дети (с возрастом), звёздность, питание, рейтинг отеля, конкретный отель,
  туроператоры (в т.ч. один — для сравнения одного ТО на двух сайтах),
  чартер/прямой рейс/трансфер/моментальное подтверждение, диапазон цен и валюта.
- **Параллельный запуск** площадок (asyncio); падение одной не валит прогон.
- **Замер времени** от старта поиска до полной загрузки результатов.
- **URL‑верификация** (Sletat и Tourvisor‑туры): после поиска параметры сверяются с
  URL результата — защита от «молчаливых» подмен (виджет показал одно, искалось другое).
  На Tourvisor фильтр операторов дополнительно применяется к выдаче, чтобы минимальная
  цена не пришла от незапрошенного оператора.
- **Health‑check гейт** (параллельный): перед прогоном проверяет, что структура форм
  площадок не изменилась (15 якорей Sletat); при поломке прогон блокируется.
- **История** прогонов в SQLite.
- **Богатый набор автотестов (600+ кейсов)** с панелью в дашборде — см. [ниже](#тесты).
- **Три интерфейса:** CLI, встроенный веб‑UI (Jinja, запасной) и React‑дашборд с живой
  трансляцией площадок и логом поиска (SSE).

## Установка

```bash
python -m venv .venv
. .venv/Scripts/activate          # PowerShell: .\.venv\Scripts\Activate.ps1
pip install -e ".[browser,web,dev]"
playwright install chromium
```

## Запуск

### Веб‑дашборд (основной интерфейс)

```bash
cd frontend && npm install && npm run build && cd ..
toursearch web                    # http://127.0.0.1:8000  (→ дашборд /app/)
```
Открой `http://127.0.0.1:8000` — корень редиректит на дашборд. Вкладки сверху:
**Поиск** (форма → «Сравнить» → живой лог SSE → отчёт), **История**, **Автотесты**.

> После изменения кода тестов/бэкенда перезапусти `toursearch web` — каталог тестов
> и эндпоинты читаются при старте. После пересборки фронта (`npm run build`) обнови
> страницу (Ctrl+F5), чтобы подтянулся новый бандл.

**Dev — с hot‑reload** (два процесса):
```bash
toursearch web                    # терминал 1: бэкенд на :8000
cd frontend && npm run dev        # терминал 2: фронт на http://127.0.0.1:5173
```

> Если фронт не собран (`frontend/dist` нет), `/` отдаёт запасную Jinja‑форму — UI
> работает даже без Node, но без оформления дашборда.

### CLI

```bash
# Туры: Москва → Турция, 3–5 ночей, 2 взрослых
toursearch search --from Москва --to Турция \
  --date-from 26.06.2026 --date-to 28.06.2026 --nights-min 3 --nights-max 5 --adults 2

# Отели (без перелёта): даты = проживание, 4–5★, всё включено, один оператор
toursearch search --to Турция --date-from 26.06.2026 --date-to 30.06.2026 \
  --mode hotels --star 4 --star 5 --meal AI --operator "Anex"

toursearch healthcheck            # проверить, что формы площадок не изменились
toursearch history                # история прогонов
```

Флаги `search`: `--mode tours|hotels`, `--child <возраст>` (повторяемый), `--resort`,
`--star`, `--meal`, `--hotel`, `--operator`, `--charter-only`, `--direct-only`,
`--price-max`, `--provider`, `--headless`, `--no-save`, `--no-check`, `--dry-run`.

> ⚠️ Sletat ограничивает окно дат вылета 13 днями; в режиме «Отели» это длина проживания.

## Архитектура

```
            ┌── CLI (typer) ─────────────┐
ввод ──►    ├── веб-UI (FastAPI + Jinja) ─┤──► SearchParams
            └── React-дашборд (/app, SSE) ┘          │
                                                     ▼
        health-check гейт (параллельный) ──► orchestrator (asyncio.gather)
                                                     │
                            ┌────────────────────────┴───────────────────┐
                     SletatProvider (Playwright)            TourvisorProvider (Playwright)
                            └────────────────────────┬───────────────────┘
                                                     ▼
                       ComparisonReport ──► reporting (отчёт) + storage (SQLite)
```

Добавить площадку = реализовать `SearchProvider` и зарегистрировать (`@register_provider`).
Оркестратор, сравнение, веб и CLI её кода не знают.

```
  providers/         base (интерфейс+реестр), sletat, tourvisor, _formcheck

```

## Тесты

Две системы, дополняющие друг друга:

**1. Быстрый pytest‑сьют (для CI)** — без сети/браузера, ~4 с:
```bash
pytest -q                               # модели, парсинг, URL, сравнение, CLI, web, storage
pytest -q --cov=toursearch              # с покрытием (ядро ~100%, cli/web ~90%)
```
CI (GitHub Actions) гоняет его на каждый push/PR и выкладывает артефактами
`coverage.xml` + `junit.xml`. Живые (e2e) тесты в CI исключены — они в панели.

**2. Панель «Автотесты» в дашборде** (`/app` → вкладка) — 600+ кейсов, по смыслу:
- **Health‑check: целостность форм + логика** — быстрые детерминированные проверки
  (парсинг/URL/модели) + живая проверка, что 15 якорей формы Sletat на месте (гейт перед поиском).
- **Live: Смоук** — быстро: сайт жив, форма цела, базовый поиск возвращает результаты.
- **Live: Позитивные — сверка фильтров** — задаём фильтр → проверяем, что **выдача ему
  соответствует** (звёзды/рейтинг/цена/курорт/оператор/питание/ночи/рейсы/валюта + комбинации pairwise).
- **Live: Режим «Отели»** — те же сверки без перелёта.
- **Live: Покрытие** — все направления / города вылета / составы тура ищутся корректно.
- **Live: Негативные и границы** — окно дат >13, экстремальные/конфликтные фильтры → без сбоя.
- **Live: Пользовательские сценарии** — сквозные «персоны» (семья/пара/группа) целиком.
- **Live: UI формы и выдачи** — проверки отдельных элементов формы и страницы результатов.

Особенности панели:
- **Параллельный прогон** сценарных тестов (каждый — свой браузер): полный live‑набор
  ~5 ч → ~1 ч. Степень — env `TOURSEARCH_TEST_CONCURRENCY` (по умолчанию 4).
- **Секундомер** у шкалы прогресса; подробный лог (старт/✓/✗ с временем).
- **Отчёт по LIVE‑тестам:** время каждого + **скриншот страницы сайта** (зум по клику);
  при ошибке — текст ошибки и скриншот.

> Один реальный поиск Sletat ≈ 60–90 с, поэтому полный live‑набор — долгий (часы);
> запускай нужные разделы/группы, а быстрый pytest — постоянно.

```bash
cd frontend && npm run build   # проверка сборки фронта
```
