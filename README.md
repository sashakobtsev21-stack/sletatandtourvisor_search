# toursearch — сравнение поиска туров на нескольких площадках

Сервис принимает параметры поиска, открывает несколько онлайн-площадок
(**Sletat** — главная, **Tourvisor**) через headless-браузер, выставляет заданные
фильтры, дожидается полной загрузки результатов, сохраняет их и **сравнивает**:
минимальная цена, по какому туроператору/отелю, лучший вариант и время выполнения
поиска на каждой площадке.

**Стек:** Python 3.12+, Playwright (async), pydantic v2, SQLite, FastAPI, pytest.
Опциональный фронт-дашборд — React 18 + Vite + Tailwind + framer-motion.

---

## Возможности

- **Два режима поиска:** «Туры» (с перелётом) и «Отели» (без перелёта, только
  проживание; на Sletat ночи в этом режиме задаются датами проживания, не отдельным
  контролом).
- **Полный набор фильтров:** город вылета, страна и курорт прилёта, даты, ночи,
  взрослые и дети (с возрастом), звёздность, питание, конкретный отель, туроператоры
  (в т.ч. один — для сравнения одного ТО на двух сайтах), чартер/прямой рейс,
  диапазон цен.
- **Параллельный запуск** площадок (asyncio); падение одной не валит прогон.
- **Замер времени** от старта поиска до полной загрузки результатов.
- **URL-верификация** (Sletat): после поиска параметры сверяются с URL результата —
  защита от «молчаливых» подмен (виджет показал одно, искалось другое).
- **Health-check гейт** (параллельный): перед прогоном проверяет, что структура форм
  площадок не изменилась; при поломке прогон блокируется с понятным отчётом.
- **История** прогонов в SQLite.
- **Три интерфейса:** CLI, встроенный веб-UI (Jinja) и опциональный React-дашборд
  с живой трансляцией площадок и логом поиска (SSE).

## Установка

```bash
python -m venv .venv
. .venv/Scripts/activate          # PowerShell: .\.venv\Scripts\Activate.ps1
pip install -e ".[browser,web,dev]"
playwright install chromium
```

## Запуск

### Вариант 1. Встроенный веб-UI (ничего больше не нужно)

```bash
toursearch web                    # http://127.0.0.1:8000
```
Форма всех фильтров → «Сравнить» → живой лог поиска (SSE) → отчёт сравнения.
Вкладки «История» и «Автотесты». Это самый простой способ — один процесс, без Node.

### Вариант 2. React-дашборд (красивый UI с live-окнами площадок)

Дашборд ходит на тот же бэкенд (`/search/prepare` → SSE `/search/stream` → `/run/{id}`).

**Прод — одним процессом** (собрать фронт один раз, дальше раздаёт FastAPI):
```bash
cd frontend && npm install && npm run build && cd ..
toursearch web                    # дашборд: http://127.0.0.1:8000/app/
```

**Dev — с hot-reload** (два процесса):
```bash
toursearch web                    # терминал 1: бэкенд на :8000
cd frontend && npm run dev        # терминал 2: фронт на http://127.0.0.1:5173
```
В dev Vite проксирует `/search`, `/run`, `/screenshots`, `/history` на бэкенд
(адрес меняется через `TOURSEARCH_API`, дефолт `http://127.0.0.1:8000`).

### Вариант 3. CLI

```bash
# Туры: Москва → Турция, 3–5 ночей, 2 взрослых
toursearch search --from Москва --to Турция \
  --date-from 26.06.2026 --date-to 28.06.2026 --nights-min 3 --nights-max 5 --adults 2

# Отели (без перелёта): даты = проживание (заезд→выезд), 4–5★, всё включено, один оператор
toursearch search --to Турция --date-from 26.06.2026 --date-to 30.06.2026 \
  --mode hotels --star 4 --star 5 --meal AI --operator anex

toursearch healthcheck            # проверить, что формы площадок не изменились
toursearch history                # история прогонов
```

Полезные флаги `search`: `--mode tours|hotels`, `--child <возраст>` (повторяемый),
`--resort`, `--star`, `--meal`, `--hotel`, `--operator`, `--charter-only`,
`--direct-only`, `--price-max`, `--provider`, `--headless`, `--no-save`,
`--no-check` (пропустить гейт), `--dry-run`.

> ⚠️ Sletat ограничивает окно дат вылета 13 днями; в режиме «Отели» это длина
> проживания (выезд минимум на день позже заезда).

## Архитектура

```
            ┌── CLI (typer) ─────────────┐
ввод ──►    ├── веб-UI (FastAPI + Jinja) ─┤──► SearchParams
            └── React-дашборд (/app, SSE) ┘          │
                                                     ▼
        health-check гейт (параллельный) ──► orchestrator (asyncio.gather)
                                                     │
                            ┌────────────────────────┴───────────────────┐
                     SletatProvider (Playwright)            TourvisorProvider (Playwright)
                            └────────────────────────┬───────────────────┘
                                                     ▼
                       ComparisonReport ──► reporting (отчёт) + storage (SQLite)
```

Добавление новой площадки = реализовать интерфейс `SearchProvider` и
зарегистрировать его (`@register_provider`). Оркестратор, сравнение, веб и CLI
её кода не знают.

## Структура

```
src/toursearch/
  models.py          SearchParams, Offer, HotelOffer, ProviderResult, ComparisonReport
  orchestrator.py    параллельный прогон площадок
  healthcheck.py     гейт «формы не сломаны» (параллельный)
  urlcheck.py        сверка параметров поиска по URL результата
  reporting.py       текстовый отчёт сравнения
  storage.py         история прогонов в SQLite
  cli.py             команды search / web / healthcheck / history
  web.py             FastAPI: форма, SSE-поиск, /run/{id}, история, автотесты
  refdata.py         справочники (города/страны/операторы) для формы
  providers/         base (интерфейс+реестр), sletat, tourvisor, _formcheck
  testkit/           собственный каталог автотестов (для веб-вкладки)
frontend/            React-дашборд (Vite); собранный dist раздаётся под /app
tests/               unit/интеграция (+ e2e против живых сайтов)
SITES.md             карта фильтров и выверенные селекторы площадок
```

## Тесты

```bash
pytest                # unit/интеграция (быстрые, без сети)
pytest -m e2e         # живые тесты против реальных сайтов (ловят редизайн)
cd frontend && npm run build   # проверка сборки фронта
```
CI (GitHub Actions) гоняет быстрые тесты на каждый push/PR (e2e исключён).

## Документация

- `PLAN.md` — план миграции и принятые решения.
- `SITES.md` — карта фильтров и выверенные селекторы обеих площадок.
- `RESULTS.md` — структура выдачи, динамика загрузки, сигналы завершения, режимы.
- `scripts/` — скрипты живого анализа/мониторинга сайтов (основа health-check).
