# Черновик плана: переписывание сервиса сравнения поиска туров

> Статус: **ЧЕРНОВИК**. Помеченные `❓` пункты требуют уточнения у заказчика.
> Дата: 2026-05-30.

## Принятые решения (согласовано с заказчиком)

- **Глубина данных:** как сейчас — оператор + минимальная цена (без отеля/рейса/питания).
- **Интерфейс:** веб-интерфейс сразу (FastAPI + форма ввода и просмотр результатов).
- **Хранение:** SQLite — сохраняем все прогоны, ведём историю.
- **Git:** переписываем историю по фазам, даты с 23 марта, без `Co-authored-by`. Force-push безопасен (репозиторий не форкали).
- **Туристы:** поддерживаем взрослых **и детей** (с возрастом детей).
- **Авторизация:** логин на `sletat.ru/b2b/` не требуется — поиск доступен без входа.
- **Полный набор входных фильтров (обновление):** пользователь задаёт перед прогоном не только город/страну/даты/ночи/туристов, но и курорт, звёздность, питание, тип отеля, конкретный отель, диапазон цен, чартер/прямой/без стопов/с трансфером, моментальное подтверждение и **режим без перелёта**. Полная карта фильтров обеих площадок и предлагаемая расширенная модель `SearchParams` — в `SITES.md` (§2 и §6). Главная площадка — Sletat. Это расширяет модель и провайдеры (Фазы 2–3 дорабатываются под полный набор).
- **Режим поиска как параметр сравнения:** пользователь выбирает тип поиска — **«Туры»** (с перелётом) или **«Отели»** (без перелёта, только проживание). Сравнение всегда в одном режиме на обеих площадках. `SearchParams.search_mode: "tours" | "hotels"`. Sletat — вкладка «Отели»; Tourvisor — раздел «Поиск отелей».
- **Глубина результата по режимам:** «Туры» — оператор + минимальная цена (как сейчас); **«Отели» — по каждому отелю** (название, звёздность, питание, цена, оператор).
- **Pre-run health-check — ЖЁСТКИЙ гейт:** перед каждым реальным прогоном сравнения сначала прогоняются автотесты якорных селекторов/структуры обеих площадок в обоих режимах. Любая поломка любого сайта — прогон НЕ запускается, показываем что именно изменилось (чиним до запуска). Это защищает от «непонятных» падений в проде из-за редизайна сайта.
- **Точка отсчёта времени = полное завершение поиска:** от клика «Найти» до момента, когда выдача полностью загрузилась — все туры/отели получены, все спиннеры/прогресс-бары/лоадеры исчезли, выдача перестала меняться. Точный DOM-сигнал завершения для каждого сайта/режима выясняется в глубоком анализе и фиксируется в `SITES.md`.

## 1. Текущее состояние

Проект — один файл `main.py` (~600 строк), Python 3 + Selenium WebDriver.

- Два класса-«драйвера»: `TourvisorSearchTest` (`tourvisor.ru/search.php`) и
  `SletatSearchTest` (`sletat.ru/b2b/`).
- Каждый класс делает одно и то же по смыслу: запускает Chrome, открывает сайт,
  заполняет форму (город вылета, страна, даты, ночи, туристы, операторы, чартер),
  жмёт «Найти», ждёт завершения, парсит список **операторов с минимальной ценой**.
- Запуск — `threading`: оба сайта параллельно, затем `print` сравнения в консоль.
- Параметры поиска захардкожены в словаре `test_data` внизу файла.
- Замер времени: от клика по кнопке поиска (`search_start = time.time()`) до конца парсинга.
- README обещает `pytest` — **тестов в репозитории нет**.

### Что работает

- Базовый сценарий: оба сайта реально заполняются и парсятся, время меряется,
  результат выводится в консоль.
- Есть обход анти-бот детекта (`navigator.webdriver`), параллельный запуск.

## 2. Проблемы текущего кода

| Проблема | Последствие |
|---|---|
| Параметры захардкожены в `test_data` | Нельзя «ввести параметры» без правки кода |
| Результат только в `stdout` | Нет сохранения, истории, сравнения по времени |
| Нет моделей данных (всё `dict`/`str`, цена как `"12000 ₽"`) | Сравнивать цены нельзя без повторного парсинга строк |
| Логика браузера и парсинга в одном классе | Невозможно тестировать без реального Chrome |
| Два класса дублируют структуру, но без общего интерфейса | Добавить 3-й сайт = копипаст 250 строк |
| Голые `except:` (десятки штук) | Ошибки молча проглатываются, отладка вслепую |
| Селекторы завязаны на внутренние классы вёрстки (`TV*`, `blinchik__*`, `rdr*`) | Хрупко: смена вёрстки сайта = тихая поломка |
| `threading` + общий словарь `results` | Работает, но async чище и масштабируемее |
| Нет выбора «лучший/худший», нет конкретного тура | Не покрывает заявленную цель |
| Нет тестов, нет CI | Регрессии не ловятся |

## 3. Целевая архитектура

Слоистая структура с единым интерфейсом провайдера площадки.

```
            ┌─────────────────────────────────────────┐
            │  Точка входа: CLI / Web UI / конфиг       │  ← ввод параметров
            └───────────────────┬─────────────────────┘
                                │ SearchParams
            ┌───────────────────▼─────────────────────┐
            │           Orchestrator (async)           │  ← запускает провайдеров параллельно,
            │                                          │     меряет время каждого
            └───────┬───────────────────────┬─────────┘
                    │                       │
        ┌───────────▼────────┐   ┌──────────▼─────────┐
        │ TourvisorProvider  │   │  SletatProvider    │  ← адаптеры, общий интерфейс
        │ (Page Object)      │   │  (Page Object)     │     search(params) -> ProviderResult
        └───────────┬────────┘   └──────────┬─────────┘
                    │                       │
                    └───────────┬───────────┘
                                │ List[ProviderResult]
            ┌───────────────────▼─────────────────────┐
            │        Comparator (чистая логика)        │  ← минимум/максимум цены, лучший/худший
            └───────────────────┬─────────────────────┘
                                │ ComparisonReport
            ┌───────────────────▼─────────────────────┐
            │  Storage (JSON/SQLite) + Presentation    │  ← сохранение + вывод
            └─────────────────────────────────────────┘
```

Ключевая идея: **браузерный драйвинг отделён от парсинга, а парсинг — от сравнения
и хранения**. Сравнение и модели данных тестируются без браузера.

## 4. Стек и инструменты (рекомендация)

| Решение | Рекомендация | За / Против |
|---|---|---|
| **Язык** | Остаёмся на **Python 3.12+** | Команда уже на нём, Selenium-знания переносятся, лучшая экосистема для browser-automation. Менять язык ради смены языка — лишний риск. |
| **Браузер** | **Playwright** вместо Selenium | + Авто-ожидания (меньше `time.sleep`), встроенный трейсинг/скриншоты, нативный async, устойчивее к динамике. − Переписывание селекторов. **Рекомендую перейти.** |
| **Параллелизм** | **asyncio** (Playwright async API) вместо `threading` | Чище, без общего мутабельного словаря, проще таймауты и отмена. |
| **Модели данных** | **pydantic v2** | Валидация ввода параметров, типобезопасные `Offer`/`Result`, сериализация в JSON «из коробки». |
| **Хранение** | **SQLite** (через SQLModel/sqlite3) для истории + экспорт в **JSON** | Согласовано: ведём историю всех прогонов, можно сравнивать по времени. |
| **Ввод параметров** | **Веб-интерфейс** (FastAPI + форма) + ядро доступно как библиотека/CLI | Согласовано: UI сразу. FastAPI отдаёт форму ввода и страницу результатов; ядро поиска переиспользуется и из CLI для отладки. |
| **Тесты** | **pytest** + `pytest-asyncio` + Playwright trace | Соответствует обещанию README. |
| **Конфиг** | `pydantic-settings` / `.env` + профили поиска в YAML/JSON | Параметры вне кода. |

## 5. Модель данных

```python
SearchParams:
    departure_city: str
    destination_country: str
    date_from: date
    date_to: date
    nights_min: int
    nights_max: int
    adults: int
    children_ages: list[int] = []   # дети с возрастом; пусто = без детей
    operators: list[str] = []  # пусто = все
    charter_only: bool = False
    direct_only: bool = False

Offer:                         # одно предложение
    provider: str              # "tourvisor" | "sletat"
    operator: str              # унифицированное имя оператора
    price: Decimal             # число, не строка!
    currency: str              # "RUB"
    raw_label: str             # исходный текст для отладки
    # отель/рейс/питание не парсим (глубина «как сейчас»); заложить как опциональные поля на будущее

ProviderResult:
    provider: str
    success: bool
    duration_seconds: float    # от клика «Найти» до конца парсинга
    offers: list[Offer]
    error: str | None
    screenshot_path: str | None

ComparisonReport:
    params: SearchParams
    run_at: datetime
    results: list[ProviderResult]
    cheapest: Offer | None     # лучший (мин. цена)
    most_expensive: Offer | None
    fastest_provider: str
    slowest_provider: str
```

**Важно при унификации:**
- Имена операторов различаются между площадками (`FUN&SUN (TUI)` vs `funsun`) — нужна
  таблица соответствия (нормализация).
- Цену хранить числом (`Decimal`), а не строкой `"12000 ₽"`, иначе сравнение невозможно.
- Валюту приводить к единой (обе площадки сейчас в рублях — зафиксировать допущение).

## 6. Устойчивость к изменениям вёрстки

- Все селекторы — в одном месте на провайдер (Page Object / отдельный модуль `selectors.py`).
- Playwright auto-wait + явные таймауты вместо `time.sleep`.
- При падении одного провайдера — **не валить весь прогон**: вернуть `ProviderResult(success=False)`,
  сохранить скриншот и trace, продолжить сравнение по выжившим.
- Структурное логирование (`logging`/`structlog`) вместо `print` и проглоченных `except`.
- Health-check селекторов: smoke-тест, который раз в день проверяет, что ключевые элементы
  ещё на месте (ловит редизайн сайта до того, как сломается прод).

## 7. Стратегия тестирования

| Уровень | Что тестируем | Как |
|---|---|---|
| **Unit** | Comparator, модели, нормализация операторов, парсинг цены | Чистые функции, без браузера — быстро и стабильно |
| **Парсинг (integration)** | Извлечение офферов из HTML | На **сохранённых HTML-фикстурах** (snapshot страниц результатов), без сети |
| **Адаптеры (integration)** | Заполнение формы | Playwright против локально сохранённой/замоканной страницы где возможно |
| **E2E smoke** | Полный прогон на реальных сайтах | Помечен `@pytest.mark.e2e`, гоняется отдельно (не в каждом PR), проверяет «поиск завершился и вернул ≥0 офферов», **не** конкретную цену (цены динамические) |

- Динамические цены → ассертить структуру и инварианты (цена > 0, оператор не пустой,
  `duration > 0`), а не значения.
- CI (GitHub Actions): unit + parsing на каждый push; e2e — по расписанию/вручную.

## 8. Расширяемость (на перспективу)

Добавление новой площадки = один новый класс, реализующий интерфейс:

```python
class SearchProvider(Protocol):
    name: str
    async def search(self, params: SearchParams) -> ProviderResult: ...
```

Провайдеры регистрируются в реестре; оркестратор и сравнение их кода не знают.
Третий/четвёртый сайт **не реализуем сейчас**, но интерфейс закладываем.

## 10. План приведения git-истории в порядок

Цель: аккуратная, последовательная история с осмысленными коммитами и мержами
feature-веток в `main`, **с датами начиная с 23 марта**, **без `Co-authored-by`** и любых
упоминаний соавторов/AI.

Подход (обсуждаемо):

1. Зафиксировать текущий код как точку отсчёта (бэкап ветки).
2. Перестроить историю по фазам из раздела 9: на каждую фазу — feature-ветка
   (`feat/skeleton`, `feat/comparator`, `feat/provider-tourvisor`, …) и merge в `main`.
3. Даты коммитов распределить от 23 марта к настоящему — через
   `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE` при коммите.
4. Сообщения — в едином стиле (Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`).
5. **Гарантированно без соавторства:**
   - в командах коммита не добавлять строку `Co-authored-by`;
   - проверить шаблон коммита (`commit.template`) и хуки — убрать авто-вставку;
   - финальная проверка: `git log --format='%an <%ae>%n%b'` не содержит `Co-authored-by`.
6. ❓ Если история уже в общем удалённом репозитории и её кто-то форкал — переписывание
   (force-push) согласовать; иначе делаем чистую новую историю.

> Примечание: «красивая история задним числом» — это переписывание, а не отражение
> реальной работы. Уточнить, что это осознанное требование заказчика.

## 12. Готовность к старту

Все решения приняты. Стек подтверждён: **Python 3.12 + Playwright + pydantic + SQLite + FastAPI**, тесты на pytest. Можно начинать с Фазы 0 (каркас).
```
